# go_proxy_mux v1.2.0

This release improves long HTTP downloads, limits repeated failed proxy logins, and hardens the Docker image and Compose deployments.

## Changes

- The HTTP setup timeout now ends when response headers arrive. Downloads and streams can continue beyond `proxy.timeout` while data keeps flowing. The new `proxy.response_body_idle_timeout` stops a response after 2 minutes without body data by default.
- Basic authentication now blocks a source IP for 5 minutes after 10 failed attempts within a 1-minute window. Blocked requests receive `429` and `Retry-After`. The thresholds, durations, and maximum of 4096 tracked IPs are configurable in YAML or `.env`.
- The Docker image runs as a non-root user. Both Compose variants use a read-only root filesystem, drop Linux capabilities, and disable privilege escalation. Base images are pinned by digest, with weekly Dependabot checks for updates.
- Local load benchmarks cover HTTP forwarding, HTTP/1.1 and HTTP/2 CONNECT, and SOCKS5 CONNECT. CI also checks slow tunnel cleanup and exercises the built image with TLS and a read-only private key.

## Upgrade notes

Existing configurations use the new timeout and authentication defaults without adding fields. If `config.yaml` or the TLS private key has mode `0600`, set `PROXY_RUN_UID` and `PROXY_RUN_GID` in Compose to an unprivileged identity that can read those files, or grant the chosen group read access. The default container identity is `1000:1000`.

Prebuilt binaries for Linux, macOS, and Windows and the Compose examples are attached to this release with `SHA256SUMS`. The multi-platform Docker image is published as `hightemp/go_proxy_mux:1.2.0` and `hightemp/go_proxy_mux:latest`.
